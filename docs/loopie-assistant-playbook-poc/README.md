# Loopie Integrated Assistant Playbook POC

This package contains implementation-ready planning documents for the deterministic integrated Assistant playbook system.

## Files

- `01-requirements.md` — product and system requirements.
- `02-feature-analysis.md` — product/architecture analysis, taxonomy, phase model, signals, UX.
- `03-poc-implementation-plan.md` — scoped developer implementation plan for the existing Loopie codebase.
- `04-expandable-taxonomy-poc.ts` — reference TypeScript taxonomy and conditional question resolver.
- `05-poc-flow-fixtures.md` — concrete Roofing/Web Development and reactive-event fixtures.

## Core direction

`LEARN → ACT → REVIEW → GROW`

- Multiple choice first.
- 3–7 choices at a time.
- Learn durable facts once.
- Reuse them across Profile, Pages, Ads, CRM, Messaging, Calendar, and future Assistant sessions.
- Playbooks are isolated content artifacts.
- Calendar is the operating surface.
- Pages, Ads, CRM, Sales, and Calendar provide live state/signals.
- Phase transitions are deterministic and explainable.
- No AI is required for the POC.

## Content rule

> **Short heading. Concrete choices. Next step.**

Avoid vague questions and long compound sentences.
