# Project State — LOOPIE

## MVP

**What it does:** A business manages owned communication (email/text/social messages), paid advertising campaigns, LOOPIE-hosted landing pages, first-party ad serving, and forms from one platform, with every lead and sale — regardless of which side generated it — landing in one shared CRM pipeline.

**Users:**

- Business users via `BusinessMembership` (OWNER / MEMBER). The initial business creator is the **Founder** (`isFounder`) — shown as Founder on the team roster and cannot be suspended or removed by others. One user can belong to multiple companies and switch active company from Profile. No MNC-staff-on-behalf-of-client portal; nested departments / custom permission matrices remain parking-lot.

**In V1:**

- Contacts & Audiences — import/create contacts, channel eligibility/consent, segment into audiences (predefined + custom filters)
- **CRM Integrations** (undocumented until the 2026-09-05 audit above — real commits `52ce215`/`52eb63e` show this shipped well before that) — `IntegrationService` + `apps/web/src/pages/crm/IntegrationsPage.tsx`: Shopify/WooCommerce/Webhook/Google Sheets/HubSpot/Salesforce connectors, OAuth kickoff, webhook-secret reveal, a WooCommerce preview-then-import flow with dedup counts, all wired to real SDK hooks (`useCrmCatalog`, `useCreateIntegration`, `useStartCrmOAuth`, `useSyncIntegration`, `usePreviewIntegration`). Feeds the same Contact/Lead graph via `ExternalContactRecord`/`ImportJob`. Not otherwise scoped in this file — treat this line as a pointer to go read the real code, not a full spec.
- Messages — compose/send email & text to an audience, save/reuse templates, automatic follow-up (max 2 steps, source-agnostic `LEAD_CREATED` trigger) that **actually runs** — see "Automation Execution" below
- Advertising — create a campaign (creative + platform + budget + dates), Deployment record per platform, tracked attribution redirect → landing page or lead capture on form submit
- **Landing Pages** — template-driven (not freeform) authoring: `LandingPageTemplate → LandingPage (draft) → PublishedPageVersion (immutable)`. LOOPIE-hosted at `/p/{slug}`, downloadable HTML export, draft/published lifecycle.
- **Forms** — first-class reusable `Form`/`FormField`, referenced by LandingPage. Submission is the canonical identity transition: anonymous session → `FormSubmission` → resolve/create Contact → create Lead, preserving Deployment/AdUnit/UTM attribution.
- **First-party advertising (AdUnit)** — a genuinely separate delivery mechanism from `Deployment` (external platforms). Served by `apps/ad-server`, a standalone deployable service sharing the same database. Feeds the same Lead/Sale spine via `sourceType = AD_UNIT`.
- Leads & Sales — one pipeline (NEW → CONTACTED → QUALIFIED → QUOTED → WON/LOST), Sale recording, attributed back to `sourceType`/`sourceMessageId`/`sourceDeploymentId`/`sourceAdUnitId` regardless of origin
- Results — Home (operational: what needs attention today) plus per-surface Performance (Campaigns → Performance, Messages → Performance); no standalone "Results"/"Reports" nav surface — see the 2026-08-27 IA revision below
- **Money & Ledger** — double-entry ledger for client ad funding, campaign budget authorization, platform spend, LOOPIE fees, credits/refunds, commissions, and payouts. Balances are derived from immutable entries.
- **Affiliate Attribution + Payouts** — a business's own referral partners: referral link/code → tracked session → Contact/Lead → Sale → Commission → Payout, backend-complete (no frontend pages yet) — see "Affiliate Attribution + Payouts" below.
- **Calendar** — goal-driven business coaching and execution center, not project management: `GoalIdeaTemplate` (content) → `lib/coachRules.ts` (which are relevant now, deterministic against real product state) → user schedules into `ScheduledGoal` → Today/This Week → Done. Every idea/goal can carry a `NAVIGATE` action straight to the exact page needed. Coaches through one fixed progression (`CoachStage`: Foundation → Attract → Capture → Convert → Grow). First-class nav tab. See "Calendar" below.
- **Teams / multi-company** — `BusinessMembership` + `BusinessInvitation` + `Session.activeBusinessId`. Profile hosts company switching + team roster; `/team` edits invites/roles/suspension; `/team/members/:userId` shows attributable metrics. Founder is the business creator. See `docs/strategy/loopie-teams-multi-company-mvp-proposal.md`.

**Parking lot (V2+):**

- Live Meta/Google/TikTok API connectors — V1 stores real `Deployment` records but platform status/spend/metrics are entered manually via `PATCH /deployments/{id}`, not synced live.
- Social post publishing to live platforms (V1 = compose/draft only).
- Branching/visual automation builder, >2-step sequences.
- Agency/multi-account/white-label management.
- Billing/subscriptions, deep role/permission systems.
- AI-generated content.
- Drag-and-drop landing-page builder (V1 is intentionally template-constrained — see below).
- Custom-domain DNS/cert provisioning for landing pages (the `customDomain` field exists; nothing automates it yet).
- A "Formerly" external landing-page template catalog/import flow (the data model — `LandingPageTemplate.businessId` nullable, `formatVersion` — is shaped for this, but no import mechanism exists).
- `DATE_REACHED` and `CONTACT_REPLIES` automation triggers — see "Automation Execution" below (**automation execution itself shipped 2026-08-27** — this used to be the whole parking-lot line; it's now just these two triggers).
- Affiliate frontend (portal/payee directory) — the backend chain shipped 2026-08-27 (Affiliate CRUD, referral tracking, auto-Commission on Sale); `pnpm pages:generate` will stub the new `/affiliates/*` routes when wanted.
- Live payment processor — `Payment` records client funding with idempotency/external refs, but no Stripe/processor plugin is installed; funding is recorded, not charged.
- Sales workflow engine (Calendar's `WORKFLOW` source is reserved for it — predefined multi-step sequences that auto-create `ScheduledGoal` rows on lead events). Also deferred: `ENTITY_STATE`/`COUNT` auto-tracking beyond the two wired metrics (page-published, qualified-lead-followups), AI-generated ideas, `OPEN_MODAL`/`START_FLOW` action types (only `NAVIGATE` is implemented), a business-configurable Playbook model (V1 has exactly one, so its order lives in the `CoachStage` enum, not editable rows), a Day calendar view (Month and Year both ship, no Week — see revision 4; List stays the primary/default view overall), `ENTITY_STATE`/`COUNT` auto-tracking for the two newest rules (Messaging/Sales-activity are MANUAL-completion only), and any frontend for reordering/snoozing beyond Complete/Dismiss/Reschedule.

**Stack:** factory defaults (Vite + React, Fastify, Prisma + MySQL) — no overrides. Two Fastify services now: `apps/server` (contract-first, everything account/business-facing) and `apps/ad-server` (plain routes, public first-party ad serving only).

**Plugins:** file-upload (Asset library), transactional email + SMS send (Messages channel delivery) — not yet installed; to confirm against `references/plugin-catalog.md` before Phase 4/5. Ad-platform OAuth connectors deferred to V2. Railway deploy config now exists for both services (`Dockerfile` + `railway.json` each) — see the `railway` plugin and "Production Ops" below for `apps/server`'s, added 2026-08-27.

**Source docs:** `docs/architecture/00-unified-data-model.md` (canonical data model — note the `architecture/` segment; this file's own citation was pointing at a dead root-level path until a 2026-09-05 audit caught it), `docs/architecture/00-unified-ia-navigation.md` (canonical IA/nav), plus the Messaging POC and Campaigns doc packs for UX/behavior detail per surface.

**Nav/model drift (2026-09-05 audit finding, corrected here):** top-level nav is no longer `Home · Campaigns · Messages · Ads · Pages · Media` as earlier entries below describe it. Per the IA doc's 2026-08-27/28 revisions: nav is now **`Home · CRM · Advertisements · Pages`** (Messages and Media both dropped from top-level nav — still fully live, reachable by direct URL and from contextual links; see the IA doc's "Legacy, Orphaned-From-Nav Surfaces" section). The paid-media surface is now backed by a newer **`Advertisement → AdRun`** model (`/ads`), not `Campaign → Deployment/AdUnit` — the older model is explicitly legacy (still on disk and functional, no longer linked from nav, never deleted per the project's "deprecated = stop writing" policy). Below, every dated entry describing "Campaign," the old nav row, or model/operation counts is a historically-accurate snapshot of that specific pass, not a claim about current totals — the schema and OpenAPI spec have both grown substantially since (check `packages/db/prisma/schema.prisma` / `packages/api-spec/openapi.yaml` directly rather than trusting a number below). A separate, in-progress pass is also extending `UserRole.ADMIN`/billing/affiliate-portal surfaces not otherwise described in this file yet — see `docs/strategy/administration-architecture-rollout.md` for that work's own current state rather than assuming this file tracks it live.
