# Project State — LOOPIE

## MVP

**What it does:** A business manages owned communication (email/text/social messages), paid advertising campaigns, LOOPIE-hosted landing pages, first-party ad serving, and forms from one platform, with every lead and sale — regardless of which side generated it — landing in one shared CRM pipeline.

**Users:**

- Single role in V1: Business user (owner/manager/marketer). No MNC-staff-on-behalf-of-client portal, no agency/multi-account layer.

**In V1:**

- Contacts & Audiences — import/create contacts, channel eligibility/consent, segment into audiences (predefined + custom filters)
- Messages — compose/send email & text to an audience, save/reuse templates, automatic follow-up (max 2 steps, source-agnostic `LEAD_CREATED` trigger) that **actually runs** — see "Automation Execution" below
- Advertising — create a campaign (creative + platform + budget + dates), Deployment record per platform, tracked attribution redirect → landing page or lead capture on form submit
- **Landing Pages** — template-driven (not freeform) authoring: `LandingPageTemplate → LandingPage (draft) → PublishedPageVersion (immutable)`. LOOPIE-hosted at `/p/{slug}`, downloadable HTML export, draft/published lifecycle.
- **Forms** — first-class reusable `Form`/`FormField`, referenced by LandingPage. Submission is the canonical identity transition: anonymous session → `FormSubmission` → resolve/create Contact → create Lead, preserving Deployment/AdUnit/UTM attribution.
- **First-party advertising (AdUnit)** — a genuinely separate delivery mechanism from `Deployment` (external platforms). Served by `apps/ad-server`, a standalone deployable service sharing the same database. Feeds the same Lead/Sale spine via `sourceType = AD_UNIT`.
- Leads & Sales — one pipeline (NEW → CONTACTED → QUALIFIED → QUOTED → WON/LOST), Sale recording, attributed back to `sourceType`/`sourceMessageId`/`sourceDeploymentId`/`sourceAdUnitId` regardless of origin
- Results — Home (operational: what needs attention today) plus per-surface Performance (Campaigns → Performance, Messages → Performance); no standalone "Results"/"Reports" nav surface — see the 2026-08-27 IA revision below
- **Money & Ledger** — double-entry ledger for client ad funding, campaign budget authorization, platform spend, LOOPIE fees, credits/refunds, commissions, and payouts. Balances are derived from immutable entries.
- **Affiliate Attribution + Payouts** — a business's own referral partners: referral link/code → tracked session → Contact/Lead → Sale → Commission → Payout, backend-complete (no frontend pages yet) — see "Affiliate Attribution + Payouts" below.

**Parking lot (V2+):**

- Live Meta/Google/TikTok API connectors — V1 stores real `Deployment` records but platform status/spend/metrics are entered manually via `PATCH /deployments/{id}`, not synced live.
- Social post publishing to live platforms (V1 = compose/draft only).
- Branching/visual automation builder, >2-step sequences.
- Agency/multi-account/white-label management.
- Billing/subscriptions, deep role/permission systems.
- AI-generated content.
- Drag-and-drop landing-page builder (V1 is intentionally template-constrained — see below).
- Custom-domain DNS/cert provisioning for landing pages (the `customDomain` field exists; nothing automates it yet).
- A "Formerly" external landing-page template catalog/import flow (the data model — `LandingPageTemplate.businessId` nullable, `formatVersion` — is shaped for this, but no import mechanism exists).
- `DATE_REACHED` and `CONTACT_REPLIES` automation triggers — see "Automation Execution" below (**automation execution itself shipped 2026-08-27** — this used to be the whole parking-lot line; it's now just these two triggers).
- Affiliate frontend (portal/payee directory) — the backend chain shipped 2026-08-27 (Affiliate CRUD, referral tracking, auto-Commission on Sale); `pnpm pages:generate` will stub the new `/affiliates/*` routes when wanted.
- Live payment processor — `Payment` records client funding with idempotency/external refs, but no Stripe/processor plugin is installed; funding is recorded, not charged.

**Stack:** factory defaults (Vite + React, Fastify, Prisma + MySQL) — no overrides. Two Fastify services now: `apps/server` (contract-first, everything account/business-facing) and `apps/ad-server` (plain routes, public first-party ad serving only).

**Plugins:** file-upload (Asset library), transactional email + SMS send (Messages channel delivery) — not yet installed; to confirm against `references/plugin-catalog.md` before Phase 4/5. Ad-platform OAuth connectors deferred to V2. Railway deploy config now exists for both services (`Dockerfile` + `railway.json` each) — see the `railway` plugin and "Production Ops" below for `apps/server`'s, added 2026-08-27.

**Source docs:** `docs/00-unified-data-model.md` (canonical data model), `docs/00-unified-ia-navigation.md` (canonical IA/nav — **Pages is a first-class top-level surface**: `Home · Campaigns · Messages · Ads · Pages · Media`; landing pages are a publishing platform with N ad spaces, not only a campaign destination), plus the Messaging POC and Campaigns doc packs for UX/behavior detail per surface.
